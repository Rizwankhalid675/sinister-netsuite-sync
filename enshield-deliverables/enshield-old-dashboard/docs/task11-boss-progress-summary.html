2Issues Found & Solutions Applied

01Authentication built on the wrong model
Found
Internal password login and the Shopify embedded-app session could share state, risking a stale internal session leaking into a Shopify context or vice versa.
Fixed
Rebuilt internal auth as a fully separate flow with its own scoped session, secure cookie, and confirmation on every dashboard route. Never conflated with the Shopify embedded session.
02Password handling wasn't production-grade
Found
No password hashing, no forced first-login change, no reset-token flow, no email confirmation on invite.
Fixed
Added scrypt-based hashing/verification, temp-password + forced change on first login, token-based reset with expiry, and email confirmation via SendGrid.
03Permissions (RBAC) incomplete and inconsistent
Found
Roles existed only informally; several routes had no permission checks at all.
Fixed
Built one canonical permissions module defining 9 standard roles. Every route now goes through shared permission-checking helpers. Confirmed users have zero access until an explicit shop-scoped role assignment exists.
04Cross-tenant (cross-shop) data leaks possible
Found
Some endpoints resolved "the current shop" from client-supplied values, which could let one merchant see another merchant's data.
Fixed
All shop-scoped routes now resolve the shop strictly from the verified session. Added tests specifically asserting cross-shop access is rejected.

2Issues Found & Solutions Applied (continued)

05Protection-price endpoint trusted a supplied shop domain
Found
A caller could pass an arbitrary shop domain, potentially probing another tenant's pricing.
Fixed
Route now fails closed unless Shopify supplies a verified app-proxy + shop context. Will work correctly once the app proxy is configured in staging.
06Finance module had no safety rails
Found
No duplicate-protection, no state machine, no currency validation, no separation of duties.
Fixed
Added a full shadow ledger: append-only journal entries, draft→submitted claim workflow, currency validation, duplicate-write protection. Finance remains shadow-only, no real postings yet.
07Some API modules could not load
Found
16 of 115 API files failed to load under plain Node.
Fixed
Corrected imports and added a permanent regression test that loads every API module. All now load cleanly.
08Logs contained sensitive data
Found
Logs captured raw request/response bodies, domains, prices, product identifiers.
Fixed
Scrubbed logging to allowlisted event codes, error names, status codes, and correlation IDs only.
09Webhooks & Shopify sync verification
Checked
Confirmed order/customer/compliance webhooks and the custom cart webhook were both present and correctly signature-verified.
Result
Standard topics handled automatically by Shopify's connection. Custom cart webhook has a dedicated, verified route. Sync config reviewed and matches usage.
10Dependency vulnerabilities
Found
Audit reported numerous advisories including some critical ones.
Fixed / remaining
Upgraded direct React Router and Vite to patched versions. Remaining criticals trace to Shopify's own CLI dev-tooling chain — needs Security sign-off or a Gadget-side refresh.

3What's Left Before Go-Live

These are approvals and staging configuration — not code fixes.

  • Shopify app proxy — configure in staging so the storefront price widget can be tested end-to-end.
  • Gadget access-control grid — needs an explicit review/grant pass by a Gadget engineer so authenticated app users can read dashboard data models in staging.
  • Staging reconciliation — compare a live Shopify/Gadget data snapshot against the dashboard/export at one fixed cutoff time.
  • Finance sign-off — written approval from Finance/CPA on chart of accounts, claims reserve treatment, and payment authority before finance leaves shadow mode.
  • Security sign-off on remaining dependency advisories.
  • Final release approvals — Product, Security, Finance, Operations, and a named release/rollback owner.
